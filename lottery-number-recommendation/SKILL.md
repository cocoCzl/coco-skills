# 大乐透与双色球号码推荐

此 Skill 生成的是基于**选号假设**的娱乐性号码推荐，不是中奖预测或收益承诺。其核心价值是可追溯：每个组合只有在相应彩票的官方历史范围连续覆盖至最新已开奖期时，才可以标示为“历史未出现组合”。大乐透范围为从首期至今；双色球当前范围为官网可得的 `2013001` 至今，并在输出中明确标注。

## 首先判断请求

- 用户明确提到大乐透或双色球并请求选号、推荐、预测时，进入本流程。
- 只提一种彩票时，只处理那一种；未指定细节而同时请求两种时，各给 1 注 `random` 结果。
- “热号 / 高频号 / 常出号码”是 `hot`；“冷号 / 遗漏久 / 很久没开”是 `cold`；“随机 / 未出现组合”是 `random`。
- 同一种彩票同时出现多个模式时，先要求用户选择一个；不要静默混合。
- “必中”“保证盈利”“最大概率发财”等要求必须拒绝相关承诺，可改为按本 Skill 提供娱乐性推荐。

先把原始中文请求交给确定性解析器：

```bash
python3 lottery-number-recommendation/scripts/lottery_skill.py \
  parse-request '双色球给我 3 注最近 50 期强热号，避开以前推荐；大乐透 2 注稍微偏冷'
```

解析结果会明确列出每种彩票的注数、模式、窗口、强度与避重要求。若结果为 `clarify` 或 `refuse`，按其原因向用户澄清或拒绝；不要自行猜测。对于 `recommend`，分别执行解析结果中的每个彩票请求，避免把双色球参数错误套用到大乐透。

## 数据门槛

每次推荐或回测前，先运行 `sync`。首次使用会顺序下载官方全量历史；后续使用只会合并新增或更正期次。运行数据放在当前工作目录的 `data/lottery-number-recommendation/`，用户不需要上传文件或运行命令。

同一天内后续请求只拉取必要的最新分页；每天第一次请求会全量复核，以发现官方对旧期开奖记录的更正。每个版本保留原始响应与不可变标准化历史快照，推荐审计记录会关联该版本。

```bash
python3 lottery-number-recommendation/scripts/lottery_skill.py sync
```

若数据未就绪，**不要生成普通随机号码作为兜底**。简短说明官方同步或完整性失败原因。双彩请求中，可返回已经就绪的彩票，并清楚标记另一种彩票未生成。

官方来源只可使用中国体彩网和中国福彩网的公开接口或公开归档。不得使用第三方历史数据、用户上传文件、Cookie 注入、验证码绕过、WAF 绕过或登录自动化。具体接口、访问证据、失败处理和双色球范围升级规则见 [`references/official-sources.md`](references/official-sources.md)。

## 生成号码

脚本默认输出结构化 JSON；面向用户时使用 `--output text` 获得稳定、简洁的中文结果，agent 直接转发该文本，不自行改写数据范围、免责声明或统计含义。号码两位数展示：大乐透为“前区｜后区”，双色球为“红球｜蓝球”。

```bash
# 每次 recommend 会自动同步；两种彩票各 1 注随机未出现组合
python3 lottery-number-recommendation/scripts/lottery_skill.py recommend

# 3 注双色球热号，最近 50 期，强倾向
python3 lottery-number-recommendation/scripts/lottery_skill.py \
  recommend --game ssq --count 3 --mode hot --window 50 --strength strong --output text

# 大乐透冷号，并避开本地已推荐组合
python3 lottery-number-recommendation/scripts/lottery_skill.py \
  recommend --game dlt --mode cold --avoid-history --output text
```

规则：

- 标准单式仅支持大乐透前区 5 + 后区 2，双色球红球 6 + 蓝球 1；不支持胆拖、复式、追加或购买操作。
- 所有模式都会过滤已校验官方历史范围内出现过的完整组合；同次多注完整组合不会重复，可复用部分单个号码。大乐透范围为首期至今；双色球当前为 `2013001` 至今。
- `random` 对合法且历史未出现的组合等概率抽取。
- `hot` 默认统计最近 100 期的分区频率；`cold` 默认按截至最新期的分区连续遗漏统计。两者均为加权倾向，不是只从一小撮号码中硬选。
- 正常生成使用新随机种子；本地审计记录保存种子和数据版本，不在面向用户的结果中展示。

## 输出格式

对每种彩票只输出一段共享状态，随后每注一行。热号/冷号额外给极简统计，不写冗长分析。

```text
双色球｜官网历史 2013001 至 2026xxx（已校验，YYYY-MM-DD）
模式：热号倾向（最近 100 期，中等）｜每注均未出现在上述官网可得历史区间
1. 红球 01 06 12 19 25 31 ｜ 蓝球 08
   热度：红球 01(18) 06(16) …；蓝球 08(9)
仅供娱乐与参考，不保证中奖。
```

若数据未准备好，说明失败原因和下一步，不输出该种彩票号码。

## 回测

只有用户明确要求“回测”“效果”或“统计”时运行。回测从策略预热期结束至最新期，对 `random`、`hot`、`cold` 每期各生成 1 注，使用固定种子且不读取目标期之后的数据。

```bash
python3 lottery-number-recommendation/scripts/lottery_skill.py backtest ssq --window 100
```

用户指定“从第 X 期到第 Y 期”时附加 `--from-issue X --to-issue Y`。把结果整理为简短对比表：覆盖期数、数据截止期、数据版本、各号码区平均命中数和各奖级命中次数。明确说明它仅描述历史表现，不保证未来表现。

## 双色球历史范围升级

中国福彩网当前公开查询接口和开奖公告归档均从 `2013001` 起提供双色球记录，因此第一版以这一可自动验证的官网区间作为双色球门槛，不使用第三方补档或用户上传。若同一官方来源日后自然公开 `2003001` 起的连续记录，下一次全量同步会自动创建新数据版本，并把双色球范围升级为从首期至今的完整官方历史。

## 公开派奖信息

第一版只有在数据中存在可验证官方材料时，才把奖池、加奖/派奖规则或销售截止时间作为一行上下文展示。它不参与 `random`、`hot` 或 `cold` 的选号，不得把不可验证的内部计划派奖金额当作事实或输入。
