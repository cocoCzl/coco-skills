# 项目发现规则

从请求目录开始盘点 Maven、Gradle、单模块、多模块和多启动应用。正式源码与资源是默认范围。

默认排除测试、示例、构建产物、生成报告、缓存、第三方目录、外部 JAR，以及指向仓库外的符号链接。只有用户明确要求时才包含测试源码。不要设置静默文件数量上限。

通过依赖声明、import、注解、API 调用、配置和文件路径共同识别持久层技术。未支持技术必须进入 `unresolved` 并使结果降级；其中可直接识别的普通 SQL仍走通用 SQL 规则。

多应用或多数据源身份无法确定时不要合并同名表。配置环境未指定时不要默认选择生产环境。

## Java 源码规则

使用本机 JDK 的语法解析能力或保守的文本提取读取项目源码，不解析依赖、不编译和不运行目标项目。

提取类、注解、字段、方法、泛型、字符串文字和可确定的简单拼接。每条事实保留原 Java 文件的相对路径和行号。字符串 SQL 的行号必须换算回 Java 文件位置。

值来自多个分支、反射、外部库、环境变量或运行时拼接时停止确认，并记录未解析项。DTO/VO/RowMapper 返回对象是查询结果角色，不能当成表。
