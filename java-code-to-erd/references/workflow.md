# 稳定分析流程

明确分析请求直接执行；只有环境疑问或实际失败才诊断。不省略事实校验。

1. 通过 `scripts/launch.py` 执行操作，环境疑问时才运行 `doctor` 检查 Python、JDK、Mermaid 和写入能力；启动器只寻找已有 Python 3.10+，禁止安装缺失工具。JDK 和 Mermaid 是可选复核能力，不影响已确认数据库事实的完成状态。
2. 确认项目根目录和用户范围。默认扫描整个项目；范围只影响最终展示，不缩小证据发现范围。
3. 运行 `analyze`。确定性工具负责盘点、解析、合并、校验和生成。
4. 根据返回的 `rule_references` 读取对应规则，只补查工具明确标为冲突或未解析的内容。
5. 检查覆盖统计、未支持技术、冲突、候选和未解析项。静态证据不足时保留未知。
6. 以 `database-model.json` 为唯一事实来源核对 ERD、DBML 和报告，禁止直接修改生成图来“修正”事实。
7. 发现人工已确认或排除的关系时使用 `review` 命令保存，再重新分析。
8. 有本地 SVG 时执行视觉检查；没有渲染器时交付 `.mmd` 并说明未完成视觉检查。

## 完成状态

- `COMPLETE`：所有已发现的相关文件已处理，模型有效，没有实质冲突或未解析的数据访问路径。JDK 语法复核或 Mermaid 渲染不可用时，分别列为环境诊断和图形检查状态，不改变此状态。
- `PARTIAL`：可靠部分可用，但存在未支持框架、冲突、动态内容或未解析文件。
- `FAILED`：无法产出通过校验的核心模型。失败时保留上一版有效报告。

## 安全边界

只读项目文件。不要连接数据库、执行 SQL 或迁移、运行 Maven/Gradle、启动项目、调用容器、联网、解析外部 JAR 或安装依赖。

## 增量与恢复

全仓发现和内容哈希校验保留；`--scope` 只影响展示。单次分析内共享读取字节，缓存命中跳过文件解析，但跨文件关系仍重新合并。每 64 个变动文件或处理阶段经过 2 秒保存原子检查点，成功结束时保存完整状态并去除已删除文件。检查点保留未访问的旧项，恢复时逐一重新校验哈希；中断后最多重做最后未落盘批次，不把缓存进度当作已发布模型。

报告先在临时目录生成；覆盖前保留受影响的旧文件，发布中发生异常时回滚已替换/删除文件，最后发布 manifest。此保证针对可处理的异常；强制终止进程或持续磁盘/权限故障可能阻止回滚，不能视为跨文件系统事务。源码字节缓存只在单次 `analyze_project` 调用内存在，正常返回或异常时均在 `finally` 恢复 ContextVar，后续扫描重新读取；进程驻留内存由 Python 管理，不承诺立即归还操作系统。
