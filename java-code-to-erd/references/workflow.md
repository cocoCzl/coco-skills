# 稳定分析流程

每次执行都按下面的顺序进行。不要根据项目熟悉程度跳步。

1. 通过 `scripts/launch.py` 运行 `doctor`，记录 Python、JDK、Mermaid 和写入能力；启动器只寻找已有 Python 3.10+，禁止安装缺失工具。JDK 和 Mermaid 是可选复核能力，不影响已确认数据库事实的完成状态。
2. 确认项目根目录和用户范围。默认扫描整个项目；范围只影响最终展示，不缩小证据发现范围。
3. 运行 `analyze`。确定性工具负责盘点、解析、合并、校验和生成。
4. 根据返回的 `rule_references` 读取对应规则，只补查工具明确标为冲突或未解析的内容。
5. 检查覆盖统计、未支持技术、冲突、候选和未解析项。静态证据不足时保留未知。
6. 以 `database-model.json` 为唯一事实来源核对 ERD、DBML 和报告，禁止直接修改生成图来“修正”事实。
7. 发现人工已确认或排除的关系时使用 `review` 命令保存，再重新分析。
8. 有本地 SVG 时执行视觉检查；没有渲染器时交付 `.mmd` 并说明未完成视觉检查。

## 完成状态

- `COMPLETE`：所有已发现的相关文件已处理，模型有效，没有实质冲突或未解析的数据访问路径。JDK 语法复核或 Mermaid 渲染不可用时，分别列为环境诊断和图形检查状态，不改变此状态。
- `PARTIAL`：可靠部分可用，但存在未支持框架、冲突、动态内容或未解析文件。
- `FAILED`：无法产出通过校验的核心模型。失败时保留上一版有效报告。

## 安全边界

只读项目文件。不要连接数据库、执行 SQL 或迁移、运行 Maven/Gradle、启动项目、调用容器、联网、解析外部 JAR 或安装依赖。
