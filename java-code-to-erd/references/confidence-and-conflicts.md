# 可信度与冲突规则

可信度由证据类别和固定规则决定，Agent 不能凭感觉提高。

| 证据 | 默认可信度 | 说明 |
|---|---|---|
| 项目 DDL 外键 | HIGH | 只证明项目文件声明，不证明线上数据库现状 |
| 明确 JoinColumn/JoinTable | HIGH | ORM 关系，不冒充物理外键 |
| 可完整解析的等值 JOIN | HIGH | 证明查询逻辑关系；方向仍需键或映射证据 |
| WHERE/HAVING 跨表等值比较 | HIGH 或 MEDIUM | 取决于别名和字段是否无歧义 |
| 项目内无歧义值传递 | MEDIUM | `CODE_INFERRED` |
| 字段命名 | LOW | 只允许形成候选 |

结论性质与可信度分开：`DECLARED`、`INFERRED`、`CANDIDATE`、`USER_CONFIRMED` 不能互相冒充。

以下情况标记冲突，不按证据数量投票：

- 相同字段被指向不同目标键；
- 两条明确证据给出相反方向；
- 数量关系无法同时成立；
- 人工复核与更新后的代码证据不一致。

数量或方向证据不足时使用 `UNKNOWN`。LEFT JOIN 只能说明这次查询允许没有匹配结果，不能证明数据库字段可空。

## 合并与校验规则

先形成逐文件观察，再解析对象身份，最后合并。相同端点的多种来源展示为一条关系，所有 Evidence 和来源类别继续保留。

明确方向证据优先用于摆正端点；未知方向的 JOIN 可以与同端点 DDL/ORM 合并，但不能反过来改变明确方向。两个明确方向相反时形成冲突。

复合键作为有序字段集合整体处理。只发现部分字段时标为不完整，不拆成多个已确认关系。人工确认使用 `USER_CONFIRMED`，排除记录保留在复核文件中，自动生成过程不得覆盖。

发布前检查：ID 唯一、引用不悬空、Evidence 存在、关系字段属于端点对象、来源枚举合法。校验失败时不替换上一版有效生成物。
