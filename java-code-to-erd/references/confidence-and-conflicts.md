# 可信度与冲突规则

可信度由证据类别和固定规则决定，Agent 不能凭感觉提高。

| 证据 | 默认可信度 | 说明 |
|---|---|---|
| 项目 DDL 外键 | HIGH | 只证明项目文件声明，不证明线上数据库现状 |
| 明确 JoinColumn/JoinTable | HIGH | ORM 关系，不冒充物理外键 |
| 可完整解析的等值 JOIN | HIGH | 证明查询逻辑关系；方向仍需键或映射证据 |
| WHERE/HAVING 跨表等值比较 | HIGH 或 MEDIUM | 取决于别名和字段是否无歧义 |
| 项目内无歧义值传递 | MEDIUM | `CODE_INFERRED` |
| 字段命名 | LOW | 只允许形成候选 |

结论性质与可信度分开：`DECLARED`、`INFERRED`、`CANDIDATE`、`USER_CONFIRMED` 不能互相冒充。

以下情况标记冲突，不按证据数量投票：

- 相同字段被指向不同目标键；
- 两条明确证据给出相反方向；
- 数量关系无法同时成立；
- 人工复核与更新后的代码证据不一致。

数量或方向证据不足时使用 `UNKNOWN`。LEFT JOIN 只能说明这次查询允许没有匹配结果，不能证明数据库字段可空。
