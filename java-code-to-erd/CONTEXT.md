# Java Code-to-ERD

该上下文定义从 Java 项目源码和项目内文件反向整理数据库模型时使用的核心语言。

## Language

**代码推导数据库模型**：
仅根据 Java 源码、映射配置、SQL、DDL 和迁移文件所能证明或推断出的数据库模型；它不连接真实数据库，也不代表任何运行环境中的实际数据库现状。
_Avoid_: 真实数据库结构、线上数据库模型

**代码中使用的表**：
在正式源码、映射配置、SQL、DDL 或有效迁移文件中被明确引用的表；该术语不表示相关代码在运行时一定执行过。默认不包含测试、示例、编译产物及第三方依赖中的引用。
_Avoid_: 运行时实际访问的表

**DDL 外键（DDL_FOREIGN_KEY）**：
在项目的 DDL 或数据库迁移文件中被明确声明的外键。它只证明项目文件中的定义；是否仍然有效取决于迁移顺序，且不代表任何真实数据库当前一定存在该外键。
_Avoid_: 真实数据库外键、物理外键、PHYSICAL_FK

**候选关系**：
只有命名规律或其他弱线索支持、尚无 DDL、ORM、SQL 或明确代码证据证明的可能关系。候选关系默认不进入 ERD 和 DBML，只作为待确认线索保存。
_Avoid_: 已确认关系、低可信度关系事实

**约束数量关系**：
由项目中的主键、唯一约束、外键或其他明确结构定义所支持的数量关系。它描述项目文件声明的数据库约束，不等于代码的使用方式。
_Avoid_: 代码数量关系

**关系可选性**：
说明关系一端是否必须存在匹配对象。数据库约束、代码映射和单条查询表达的可选性需要分别判断，证据不足时保持未知。
_Avoid_: 根据 JOIN 类型确认数据库可空性

**代码数量关系**：
由 ORM 映射、Java 字段类型、查询返回类型或业务代码表达的数量关系。它描述代码如何理解和使用关系，不表示数据库一定强制执行相同约束。
_Avoid_: 数据库保证的数量关系

**关系冲突**：
不同代码或项目文件对同一组表、字段或数量关系给出了无法同时成立的描述。冲突中的每条证据都应保留，供开发者定位配置或代码问题。
_Avoid_: 自动合并后的关系、已解决关系

**证据支持的结论**：
能够由项目中的具体文件位置和内容直接支持的分析结果。静态分析无法确定的内容应作为未解析项保留，不能为了完整性而补猜。
_Avoid_: 无依据结论、运行时事实

**分析范围**：
默认覆盖当前仓库内的整个项目及其 Java 多模块源码，不主动扫描第三方 JAR 或本机依赖缓存。用户指定模块或表时，先进行全项目发现，再深入分析目标范围及其直接相关代码，并单独说明跨范围关系。
_Avoid_: 只扫描用户点名的文件

**表身份**：
由数据源、schema 和表名共同确定的表标识。同名表只有在这些信息能够对应时才允许合并；信息不足时应保留为归属未知的独立对象。
_Avoid_: 只用表名标识表

**表发现状态**：
说明一张表是在 DDL 与代码中同时发现、仅在 DDL 中发现，还是仅在代码中发现。该状态用于区分项目结构定义、应用访问证据和可能的遗留内容。
_Avoid_: 表是否真实存在

**项目声明的当前结构**：
按照项目内可确定的数据库迁移顺序，还原出的最终表结构状态。迁移顺序或启用条件无法确定时，相关对象的当前状态也应标记为无法确定。
_Avoid_: 真实数据库当前结构、迁移文件全集

**汇总关系**：
对相同表和字段之间多种关系证据的统一展示。每种来源仍作为独立证据保留；证据发生矛盾时，汇总关系应标记为关系冲突。
_Avoid_: 重复关系、覆盖原始证据

**关系方向**：
`from` 表示保存引用字段的一方，`to` 表示被引用键的一方，与 SQL 中对象出现顺序无关。无法根据键、映射所有方或代码逻辑确定时应保持方向未知。
_Avoid_: SQL 书写顺序、任意箭头方向

**代码对象映射**：
Java 类与数据库对象之间带有角色说明的对应关系。它允许多对多映射，不能预设一张表只对应一个 Entity、Mapper、Repository 或 DAO。
_Avoid_: 表与 Java 类一一对应

**查询结果对象**：
承接单表或多表查询结果的 DTO、VO 或类似 Java 对象。它可以记录字段来源和返回它的数据访问代码，但不能因此被视为某张表的 Entity。
_Avoid_: Entity、数据库表

**结论性质**：
说明分析结果属于明确声明、代码推断还是候选关系。它与可信度及冲突状态分别记录，不能混为同一组等级。
_Avoid_: 置信度

**可信度**：
说明某条结论在现有证据支持下的可靠程度，使用高、中、低表达。可信度不负责表示结论是否由代码直接声明，也不负责表示证据间是否冲突。
_Avoid_: 结论性质、冲突状态

**可信度规则**：
根据证据类型、完整程度、独立证据印证情况及歧义程度确定可信度的固定规则。AI 可以因证据缺失降低可信度，但不能在没有新增证据时自行提高可信度。
_Avoid_: AI 主观评分

**证据位置**：
支持某项结论的项目相对文件路径和行号。默认不保存或展示原始代码片段，分析报告也以结论为主。
_Avoid_: 完整代码副本、证据代码片段

**增量分析**：
复用未变化文件的分析结果，只重新处理新增、修改或删除的文件，再依据当前全部有效证据重建最终模型。已经失去全部证据的旧结论不能继续保留。
_Avoid_: 保留旧模型后追加结果、完整结果缓存

**动态表模式**：
表名中含有只能在运行时确定部分的数据库对象引用，例如 `user_${tenantId}`。它不是一张已确定的表，只有在所有可能值均能从项目中证明时才允许展开。
_Avoid_: 确定表、猜测出的分表名称

**数据库对象**：
项目代码引用的持久表、视图、物化视图、临时对象或类型未知对象的统称。SQL 中出现的名字只有在证据足够时才具体认定为表或某类视图。
_Avoid_: 一律称为表

**数据库对象依赖**：
视图、存储过程、数据库函数或触发器读取、写入或调用其他数据库对象形成的依赖。它说明项目文件中的访问关系，不能自动视为数据库外键。
_Avoid_: 数据库外键、Java 代码关系

**数据库访问方式**：
代码或 SQL 对数据库对象及字段进行查询、新增、修改、删除、结构变更或间接调用的使用分类。它描述项目文件表达的操作，不证明运行时已经执行。
_Avoid_: 运行时操作记录、仅出现过

**可能名称**：
根据命名习惯推测、但未被项目配置或明确映射证明的表名或列名。可能名称只能用于辅助匹配和提示，不能单独支持确认关系。
_Avoid_: 已确认名称、数据库真实名称

**名称分类**：
数据库对象的查询别名、迁移历史名称、可能名称和 DDL 同义词属于不同概念，必须分别记录。查询别名只在所属 SQL 中有效，不能成为数据库对象身份的一部分。
_Avoid_: possibleAliases、统一别名列表

**名称标准化**：
在保留原始写法的同时，依据已识别数据库对大小写和引号的规则生成匹配名称。数据库类型未知或标识符带来歧义时，只能标记可能相同，不能自动合并。
_Avoid_: 全部转小写、忽略引号合并

**默认 ERD**：
展示 DDL、ORM、SQL 或代码证据支持的高、中可信度关系，并明确标注来源。候选关系和关系冲突默认只进入分析报告，不作为正常关系画入图中。
_Avoid_: 仅外键图、包含候选关系的 ERD

**人工复核**：
用户对候选关系或自动结论作出的确认、排除或修正。人工复核需要跨运行保留并与代码证据分开，新代码证据与其矛盾时应重新提示。
_Avoid_: 代码证据、自动确认

**结果映射关系（RESULT_MAPPING）**：
由 MyBatis 等映射配置表达的单对象或对象集合关系。它说明查询结果如何组织为 Java 对象，不表示数据库声明了外键。
_Avoid_: ORM 关系、数据库外键

**SQL 字段比较（SQL_COLUMN_COMPARISON）**：
在 `WHERE`、`HAVING` 等 SQL 条件中发现的跨数据库对象字段比较。等值比较可以支持逻辑关系，非等值比较默认只说明查询依赖。
_Avoid_: SQL JOIN、数据库外键

**分析方式**：
包括全项目分析、指定范围分析和单个数据库对象关系查询。分析方式决定输出范围，但不会阻止 Skill 在项目其他位置寻找与目标直接相关的证据。
_Avoid_: 固定生成全部文件

**可读 ERD**：
布局、分组、命名、配色、图例和关系标记保持一致，且在表和关系较多时仍能清楚阅读的关系图。关系含义不能只依赖颜色表达；Mermaid 源文件始终保留，本地可渲染时同时提供可直接查看的 SVG。
_Avoid_: 只保证语法有效的关系图、装饰性图表

**ERD 视觉检查**：
将 Mermaid 实际渲染后检查截断、重叠、密度、标签、图例和关系方向，并在需要时重新布局或拆图。本地无法渲染时只能声明完成语法检查，不能声称完成视觉检查。
_Avoid_: Mermaid 语法检查

**逻辑关系图**：
展示已有证据支持、但数量关系无法确定的数据库对象关系。它使用普通关系线和未知标记，避免在 Crow’s Foot ERD 中编造 `1:1`、`1:N` 或 `N:M`。
_Avoid_: Crow’s Foot ERD、候选关系图

**条件关系**：
只在动态 SQL、配置或代码分支满足特定条件时才会使用的关系。它可以具有明确证据和高可信度，但不能描述成每次执行都会发生。
_Avoid_: 无条件关系、候选关系

**稳定输出**：
相同项目输入应生成内容和顺序一致的核心模型、报告及图表。运行时间等易变化信息应与核心结果分开，避免制造无意义差异。
_Avoid_: 每次运行都变化的生成文件

**分析覆盖情况**：
对发现、已分析、跳过和未解析的 Java、映射及 SQL 文件进行汇总统计，并列出会影响完整性的问题文件。它用于说明分析范围，不要求罗列全部正常文件。
_Avoid_: 无法验证的完整分析声明

**应用边界**：
同一仓库中可独立运行或配置数据访问的 Java 应用范围。各应用默认分别建模，只有数据库对象身份能够确认一致时才允许在仓库总览中合并。
_Avoid_: 仓库即单一应用

**字段类型**：
分别记录 Java 类型和有证据支持的数据库类型。Java 类型不能直接充当已确认的数据库类型；缺少数据库类型证据时应保持未知。
_Avoid_: 根据 Java 类型确认的数据库类型

**值传递关系**：
同一个业务值在项目自身代码中经过字段读取、参数、返回值或方法调用，最终用于访问另一个数据库对象时形成的代码推断关系。来源不唯一或追踪进入无法静态解析的逻辑时，该关系必须标记为不确定。
_Avoid_: 数据库外键、字段同名关系

**配置环境**：
由项目配置区分、可能影响数据源、schema、迁移文件或数据库对象解析结果的运行配置集合。无法确定当前启用环境时，各环境差异必须分开保留。
_Avoid_: 默认生产环境、合并后的配置

**分析状态**：
分析结果分为完整、部分完成和失败。存在未解析内容或关系冲突但核心模型仍有效时属于部分完成，不能对外声称已经完整覆盖项目。
_Avoid_: 有输出即分析完成
