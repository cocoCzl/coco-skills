# AI Resume Expert 开发任务拆分

来源：[PRD：AI Resume Expert](./PRD-ai-resume-expert.md)

## 拆分原则

- 每个任务都是一个可演示、可验证的端到端 tracer-bullet，不是只写某层文件的横向任务。
- 每个任务在其依赖完成后可由一个 Codex 会话独立领取和完成。
- 每个任务同时包含该切片所需的 Skill 指令、参考资料、示例、行为评测或确定性测试；不把测试统一拖到最后。
- `AFK` 表示需求已经明确，可独立实施；`HITL` 表示完成时需要用户进行视觉或产品确认。
- 所有测试材料使用虚构或充分脱敏内容；不得提交真实简历、公司代码或个人信息。
- 本文是本地 Issue 草案，不创建外部 Issue Tracker 条目。

- AIRES-001～AIRES-023 的实现和自动回归已完成。PDF 的本地能力缺失或失效时，测试会明确降级；不会把跳过的真实渲染测试写成已通过。

## AIRES-001：建立可安装入口与目标岗位路由

**Type**：AFK<br>
**Blocked by**：None - can start immediately<br>
**User stories covered**：US-1、US-49、US-50<br>
**PRD coverage**：FR-1、NFR-3、NFR-6、NFR-7；AC-01、AC-05、AC-06

### What to build

建立可独立安装的 `ai-resume-expert` 最小 Skill，并完成“用户请求 → 目标岗位确认 → 支持范围判断 → 请求模式路由”的完整窄路径。该切片不生成正式简历，但必须能够正确处理缺少目标岗位、受支持技术岗位和不支持职业三类请求，并为后续切片提供稳定入口。

### Acceptance criteria

- [x] Skill 主入口和面向使用者的 README 均存在，仓库结构检查能够发现该 Skill。
- [x] 触发描述覆盖简历生成、代码/文档生成、简历诊断、简历优化、JD 定制和 PDF 等核心中文意图。
- [x] 用户未说明目标岗位时，只自然询问目标岗位，不生成简历或批量问卷。
- [x] 受支持岗位被规范映射到首版岗位族和默认中国大陆中文语境。
- [x] 不支持岗位进入有限降级，并明确不声称专家优化或投递就绪。
- [x] 请求可被分类为直接描述、代码/文档、诊断、优化或混合模式。
- [x] 至少提供缺少目标岗位和不支持岗位两个最高层行为评测。
- [x] README 说明首版范围、模型主体、离线优先和不保证录用的边界。

## AIRES-002：直接描述生成后端岗位基准版

**Type**：AFK<br>
**Blocked by**：AIRES-001<br>
**User stories covered**：US-2、US-7、US-10、US-21～US-26、US-31、US-40、US-41<br>
**PRD coverage**：FR-4、FR-6、FR-7、FR-8、FR-11；AC-02、AC-07～AC-12、AC-16、AC-27～AC-31、AC-37、AC-39

### What to build

打通第一个完整生成路径：有经验的后端工程师直接提供目标岗位、职级、任职时间线和充分经历后，Skill 建立职业事实、应用 STAR 与后端岗位策略、自审并交付岗位基准版 Markdown 初稿及最小证据追踪信息。

### Acceptance criteria

- [x] 对信息充分的后端案例生成完整岗位基准版 Markdown，不声称完成 JD 匹配。
- [x] Markdown 初稿包含最小必要个人信息结构、个人简介、证据化技能、公司经历、公司核心项目和教育信息的适用子集。
- [x] 每段入选经历均包含已确认的个人角色、关键行动或技术方案，以及可核查量化结果或真实定性结果。
- [x] 项目事实、个人贡献和用户确认事实在生成前保持不同状态。
- [x] 没有可靠数字时不产生百分比、倍数或虚构规模。
- [x] 核心技能能在经历中找到支撑，无技能进度条、百分比或无证据“精通”。
- [x] 正式文案使用 STAR 证据但不显示机械的 S/T/A/R 标签。
- [x] 用户可见初稿经过基本事实、岗位、重复、篇幅和保密自审。
- [x] 使用虚构后端经历提供一条完整行为评测和一个可读示例。

## AIRES-003：补齐自适应对话式职业访谈

**Type**：AFK<br>
**Blocked by**：AIRES-002<br>
**User stories covered**：US-11～US-15<br>
**PRD coverage**：FR-5、FR-6、NFR-4；AC-13～AC-16

### What to build

将信息不足的直接描述路径升级为自然、上下文感知的职业访谈。Skill 根据最低证据门槛一次询问一个最有价值的问题，能提供不诱导的候选回答方向，并允许用户切换到批量结构化问卷。

### Acceptance criteria

- [x] 缺少目标岗位时仍由目标岗位问题优先，其他问题不抢跑。
- [x] 缺少个人角色、行动、技术方案或结果时，每轮只询问当前最影响质量的一项。
- [x] 问题引用用户已经提供的具体上下文，不使用机械表单式话术。
- [x] 已回答或可从材料确认的信息不会被重复询问。
- [x] 候选回答方向明确标为候选，并允许用户回答“都不是”。
- [x] 候选回答未经明确确认不会进入职业事实或简历。
- [x] 用户要求快速填写时返回一次性结构化问卷。
- [x] 达到最低证据门槛后停止访谈并进入生成，不为走流程继续提问。
- [x] 行为评测覆盖单问模式、批量模式、拒绝候选答案和信息充分直接生成。

## AIRES-004：增加 JD 定制与多目标岗位分流

**Type**：AFK<br>
**Blocked by**：AIRES-002、AIRES-003<br>
**User stories covered**：US-3～US-5、US-38<br>
**PRD coverage**：FR-1、FR-9；AC-03、AC-04、AC-29、AC-33

### What to build

增加具体 JD 的要求提取、证据映射和岗位定向改写，并处理一个用户同时提供多个目标岗位的场景。交付物包括 JD 要求覆盖和一个只使用证据化关键词的定制 Markdown 初稿。

### Acceptance criteria

- [x] JD 要求被分类为已证实、部分证实、未证实或不相关。
- [x] 只有能够关联职业事实的 JD 关键词进入简历正文。
- [x] 未满足要求只出现在证据差距中，不被改写成已有能力。
- [x] 真实经历可使用 JD 的等价专业术语，但不得扩大个人职责或熟练度。
- [x] 输出不包含 ATS 匹配百分比、录用概率、隐藏关键词或机械堆词。
- [x] 没有 JD 时继续生成岗位基准版，并明确其版本类型。
- [x] 多个明显不同的目标岗位触发分别生成岗位定向版本的建议。
- [x] 明确交叉岗位可合并定位，并解释为什么不属于多方向通投。
- [x] 行为评测覆盖岗位基准版、JD 定制版、多岗位分流和无证据关键词拒绝。

## AIRES-005：增加项目入选建议与经历归属

**Type**：AFK<br>
**Blocked by**：AIRES-002<br>
**User stories covered**：US-28～US-30<br>
**PRD coverage**：FR-7、FR-8；AC-24～AC-26、AC-30

### What to build

当用户有多个公司项目、个人项目和开源项目时，Skill 对候选项目排序，给出 2～4 个入选建议及淘汰理由，并把公司核心项目放回对应公司经历。技术转型时允许真实的个人或开源项目成为明确标注的关键补充。

### Acceptance criteria

- [x] 项目排序同时考虑岗位相关性、个人贡献、技术复杂度、结果价值、时间新旧和可辩护性。
- [x] 输出明确推荐项目、推荐理由、淘汰项目和淘汰理由。
- [x] 用户保留最终选择权，Skill 不以排序结果替代确认。
- [x] 有经验用户的公司核心项目位于对应公司经历下。
- [x] 工作描述与项目描述不存在相同内容的重复粘贴。
- [x] 普通个人项目不挤占更强的相关公司证据。
- [x] 转型证明项目明确标注为个人或开源，不伪装成公司项目。
- [x] 行为评测覆盖多项目取舍、有经验用户和 Java 转 AI 的转型场景。

## AIRES-006：按职业阶段动态组织简历

**Type**：AFK<br>
**Blocked by**：AIRES-002、AIRES-005<br>
**User stories covered**：US-6～US-9、US-41<br>
**PRD coverage**：FR-7、FR-8；AC-30、AC-31、AC-42

### What to build

让同一生成流程针对应届/实习、有经验工程师、技术方向转型、技术负责人/架构师四类职业阶段选择不同的信息架构、章节顺序和证据重点，同时保持最小个人信息与 1～2 页约束。

### Acceptance criteria

- [x] 应届/实习案例优先展示教育、实习、课程项目、竞赛和开源证据。
- [x] 有经验工程师案例优先展示工作成果、公司核心项目和技术难点。
- [x] 转型案例同时展示可迁移能力和转型证明项目，不隐藏真实背景。
- [x] 技术负责人/架构师阶段预留决策、跨团队影响和系统演进信息结构。
- [x] 章节按证据价值动态出现，不要求所有用户填写同一固定模板。
- [x] 默认不加入照片、年龄、婚姻、籍贯等无关敏感身份信息。
- [x] 一页与两页策略不会通过不可读小字号强行压缩。
- [x] 每个职业阶段至少有一个行为评测或示例，验证结构差异而非固定文案。
