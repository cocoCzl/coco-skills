# 测试与验证选择

来源：三 单元测试 p.29–30。

- 【强制，1–5】测试自动化、独立、可重复；以断言判断结果，不靠打印后肉眼看；单测隔离外部网络/状态，集成测试明确环境和清理。
- 【强制，6–7】核心增量行为保证相关测试通过，新增有风险行为补回归；测试放测试 source set，缺省 src/test/java。项目已有布局优先，不迁移目录。
- 【推荐，8–9】70% 语句/核心 100% 语句和分支是手册目标，不是本 Skill 为所有项目添加的新门禁；按 BCDE 覆盖边界、正常、设计约束和错误路径。
- 【推荐，10–12】数据库测试程序化准备数据并回滚/清理；需要时在任务范围内改善可测性，不能为了测试扩大架构重构。

| 改动 | 必要验证 |
| --- | --- |
| 纯空格/换行/导入 | diff 范围与现有格式检查；确认 import 改动未改变解析；不为此生成新行为测试 |
| DTO 无行为字段 | 编译及受影响序列化/映射检查，若契约有风险运行现有相关测试；不为 getter 镜像实现 |
| 修复/重构业务 | 相关模块编译、已有静态检查、对应行为回归；覆盖本次 bug，必要时验证失败前/修复后 |
| 锁/资源/异常 | 异常路径、释放/中断/事务回滚等相关断言；超时避免挂死测试 |

只运行实际存在的构建任务，确认 Maven profile/Gradle source set 与目标模块；用项目 wrapper。通过后只有新改动或新风险才扩大/重跑。不删除测试、禁用规则、加无依据 suppression 来制造通过。已有不相关失败明确归属和影响，不能说全通过。

无 formatter/静态检查时手动检查 diff 的缩进、边界、导入、命名及场景风险，并列明未自动验证项目；不要下载工具、引入构建插件或生成强制报告。
