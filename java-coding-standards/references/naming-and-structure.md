# 命名与结构

定位均为黄山版章节及条号；只应用本次任务涉及的条目。项目明确模型和公共契约优先，不因后缀差异迁移现有类型。

- 【强制】名称不用拼音英文混杂、中文、首尾 `_`/`$` 或歧视侮辱词；类 UpperCamelCase（DO/DTO/VO 等例外），方法/变量 lowerCamelCase，常量全大写下划线；抽象类 Abstract/Base 开头，异常 Exception 结尾，测试类以被测类开头、Test 结尾；包名小写单数（一（一）1–10）。POJO 布尔字段用 `deleted`，不用 `isDeleted`；不要同时定义同一属性的 is/get 两种访问器（一（四）18）。已公开 JSON/数据库映射须保持兼容。
- 【推荐】完整语义单词、合适可见性；【参考】Enum 后缀、get/list/count/save 等分层方法名前缀，不能仅因没用它们判缺陷（一（一）13、18–19；一（四）26）。SOA 暴露的 Service/DAO 接口及 Impl 后缀是该场景【强制】，不为普通小类制造接口（一（一）17）。
- 【强制】提取具有业务含义的魔法值（一（二）1）。【推荐】按职责分常量、固定取值考虑 enum（一（二）4–6）；循环下标的 0 等语法惯用值无需机械提取为常量（融合解释）。
- 【强制】覆盖方法用 `@Override`；静态成员用类名访问；不随意变更对外接口签名，废弃接口标记替代方案；新增调用不使用已过时 API（一（四）1–5）。兼容性迁移按项目计划，不能顺手全仓替换。
- 【强制】手册 POJO 属性/RPC 参数返回用包装类型、不设 POJO 属性默认值；【推荐】局部变量用基本类型（一（四）13–14）。按数据契约保留 null/缺失/零的区别；已有非空模型、record 或框架约束按项目执行，不给所有基础类型机械装箱。
- 【强制】兼容新增序列化字段不改 serialVersionUID，不兼容升级需明确版本；构造器不放业务流程；POJO 提供 toString（一（四）15–17）。融合：只做构造不变量校验/赋值；toString 排除敏感字段，避免递归/触发懒加载；不为本来无需 Java 序列化的类添加 Serializable。
- 【强制】类/属性/方法注释采用 Javadoc，抽象方法说明功能、参数、返回、异常和调用约束；枚举项说明用途（一（九）1–2、5）。【推荐】修改行为同步注释；【参考】不重复代码字面含义（一（九）7、11）。手册要求类创建者/日期（一（九）3【强制】），本 Skill 不编造个人署名和历史日期：按项目模板/可核实元数据填写；未知时省略并说明，不为此打断普通修改（D4）。
- 【推荐】卫语句减少深嵌套，复杂条件命名；不为“80 行”或“3 层”指标无关重构（一（八）7–8）。经典 switch 每分支终止或注明落入，并带 default（一（八）1【强制】）；现代穷尽 switch 见 D7。
