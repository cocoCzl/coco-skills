# 自审与交付状态

正文形成后使用本清单；需要具体交付物时再看后文。普通诊断或 Markdown 任务用会话摘要记录来源即可，不必创建 JSON 包、职业库或固定表格。结构化交接、确定性包校验和 PDF 才需要相应包。

## 生成后自审

- [ ] 每条核心陈述有来源、个人归属确认与可披露状态；没有项目事实自动升级、冲突、待确认贡献或无依据数字。
- [ ] 单一岗位/职级明确，采用对应岗位策略；有 JD 时只写已证实的要求，无 JD 时标明岗位基准版。
- [ ] 工作经历与重点项目经历按 [通用结构规则](common-resume-rules.md#7-公司项目个人项目与重复控制) 分工，每段保留任职有 STAR 成果；项目有公司/个人归属、行动、取舍和真实结果，摘要例外有理由，两章不重复。
- [ ] 项目技术栈可追溯，核心技能有个人实践支撑；高强度动词和熟练度能解释背景、个人作用、替代方案与结果依据，不能解释的降级或删除。
- [ ] 无内部代号、客户、域名/IP、接口/表结构、源码、安全配置或敏感指标；仅改项目名不能代替脱敏。
- [ ] 最小必要个人信息、单栏文本、稳定日期与链接；默认 1～2 页，不缩字号强行压页，无隐藏词、假 ATS 分数或技能百分比。
- [ ] 当前状态与下表一致；投递就绪还需用户确认最终事实、措辞和项目选择，联系方式补齐并确认，致命问题解决，无占位符。

任一事实、归属或保密阻断项失败，只退回相关陈述补证，不将初稿标成投递就绪。最低证据门槛见主入口；详细写作标准以 [通用规则](common-resume-rules.md) 为准，不重复加载未变化资料。

## 阶段与交付状态

| 阶段 | 可交付 | 不得声称 |
|---|---|---|
| 信息不足 | 素材清单、缺口、项目建议或骨架 | Markdown 初稿、投递就绪 |
| 证据达标且自审通过 | Markdown 初稿；追踪、JD 覆盖、修改对照、面试追问按实际需要交付 | 已定稿、PDF 已确认 |
| 用户确认 Markdown | 最终 Markdown、可打印 HTML；联系方式确认后可进入 PDF | 未验收 PDF 合格 |
| PDF 自动校验和 Agent 全页视觉检查通过 | PDF、Markdown、验收摘要，可供用户审阅 | 用户已签收、ATS 保过或录用保证 |
| PDF 渲染或验收失败 | Markdown、HTML、明确失败原因 | 未生成的 PDF 已生成、未检查的视觉已通过 |

首次交付在正文之外简述版本（岗位基准版/JD 定制版）、内容状态、实际阻断项及必要下一步；无缺口不额外索取签收。只有 Markdown 初稿或之后才称“已生成 Markdown 简历”。PDF 分别报告内容确认、自动校验、Agent 视觉检查、用户审阅状态；`visual_signoff_pending` 不表示 Agent 已看图。导出时再读 [PDF 交付](pdf-delivery.md)。

## 按交付需要选择内容

- 素材清单：定位；已确认事实及披露状态；待确认素材；按阻断程度排序的缺口；冲突与保密阻断。可用短段落，不强制表格。
- 项目建议、证据追踪、JD 四态覆盖：需要这些附加材料时使用 [证据治理](evidence-jd-and-projects.md) 中的对应模板；不在简历正文添加源码引用。
- 简历正文：按 [通用规则](common-resume-rules.md) 的职业阶段结构和一个岗位策略组织；联系方式初稿可暂缺，会话中提示定稿前补齐，不在正文堆 TODO。
- 成果要点：场景/约束 + 个人动作 + 方法/取舍 + 可核查量化或真实定性结果。核实用 STAR，正文不展示四段标签。
- 面试追问：需要时独立交付，围绕背景约束、个人边界、替代方案、难点定位、结果口径、代价与复做改进选择适用问题。高熟练度技能追问独立解决的复杂实践、机制和使用边界。

投递就绪只表示满足本 Skill 的内容门槛，不保证筛选、面试或录用。
