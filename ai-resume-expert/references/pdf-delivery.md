# PDF 交付与验收

仅在用户要求 PDF 且 Markdown 内容已确认时读取；自动校验、Agent 视觉检查和用户审阅分别记录。实际报错再读 [故障排查](pdf-troubleshooting.md)。

## 1. PDF 前置门槛

只有以下条件全部满足才启动 PDF：

1. 用户明确说已确认当前 Markdown，而非沉默或只说“看起来还行”。
2. 姓名、手机、邮箱、城市及要展示的链接已由用户确认。
3. 事实、保密与可辩护性无阻断。
4. 默认输出目录为当前工作区的 `reports/ai-resume-expert/`；用户明确指定其他位置时仍须在 Skill 包外。
5. 使用本地渲染能力，不上传私人材料到第三方转换服务。

## 2. 默认 PDF 视觉规范

- 现代技术型极简风，单栏主体，克制深蓝/深灰强调色。
- 清晰的姓名、目标岗位、章节标题、公司/项目和正文层级。
- 统一网格、日期对齐、细分隔线和充足但不浪费的留白。
- 中文字体有合法的本地回退策略；正文字号保持易读。
- 文字可选择，阅读顺序稳定，链接可点击，黑白/灰度仍清晰。
- 页首外链使用短标签 Markdown 链接，不堆叠完整裸 URL。
- 禁止双栏主体、技能进度条、复杂图表、花哨背景、隐藏关键词和图片型正文。
- 默认 1～2 页；先删弱证据、合并重复和精炼文案，不先缩小字号。

## 3. PDF 验收

文件存在不等于通过。至少检查：

- [ ] 页数为 1～2 页，页面尺寸与边距稳定。
- [ ] 可提取完整中文文本，顺序与视觉一致，无乱码或缺字。
- [ ] 页面渲染图已实际检查字体、层级、对齐、留白和整体专业感。
- [ ] 无截断、重叠、异常换行、标题孤立或明显孤行寡行。
- [ ] 链接显示与目标正确，长链接未破坏布局。
- [ ] 灰度/黑白检查仍有足够对比，不依赖颜色理解结构。
- [ ] 未通过不可读小字号、极窄行距或边距强行压页。

发现问题时阻断 PDF 交付，调整内容/版式后重新渲染和验收。

自动通过不等于 Agent 已看页面。Agent 实际检查所有彩色/灰度预览后，可交付待用户审阅 PDF，无需等额外签收。分别报告内容确认、自动校验、Agent 视觉检查和用户审阅状态；`visual_signoff_pending` 不表示渲染失败。可选用户签收才获得哈希绑定的 `qualified`，不伪造用户确认。

## 4. PDF 失败降级

渲染依赖不可用、字体失败、文件超页或多次修正仍不合格时，交付：

1. 已确认的最终 Markdown。
2. 单栏、可打印、使用系统字体回退的 HTML。
3. 清楚说明“PDF 未生成/未通过验收”的原因和未检查项。
4. 可执行的后续建议，例如安装本地渲染器或改用用户已有的受信工具；不得上传到第三方在线转换服务。

不得把失败生成物标成最终 PDF。

## 5. 最终交付摘要模板

```markdown
## 交付状态
- 版本：岗位基准版 / JD 定制版
- 内容：Markdown 已确认 / 未确认
- 投递就绪门槛：通过 / 未通过（原因）
- PDF：已生成并验收 / 未生成，已降级为 Markdown + 可打印 HTML
- 页数与视觉：<仅在实际验收后填写>
- 重要边界：不保证 ATS 通过、面试或录用
```
