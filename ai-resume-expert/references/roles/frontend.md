# 前端工程师岗位策略

适用于 Web 前端、可视化前端和前端工程化岗位。核心是证明用户如何改善体验、性能、质量和交付，而不是列 React/Vue 组件和页面数量。

## 1. 路由与主线

确认目标偏业务前端、前端基础设施/工程化、数据可视化、设计系统还是低代码平台。再确认浏览器/终端范围、主要框架和目标职级。客户端/移动端另读 `client-mobile.md`；真实全栈岗位读 `fullstack.md`。

## 2. 优先寻找的证据

| 能力域 | 高价值事实 | 可用结果 | 关键确认 |
|---|---|---|---|
| 用户体验与交互 | 复杂交互、加载/错误/空状态、键盘操作、响应式 | 降低操作复杂度、提高任务完成稳定性 | 用户是否参与方案，而非只还原设计稿 |
| 性能 | 加载路径、分包、缓存、渲染、长任务、列表/图表优化 | 有来源的 Web Vitals/耗时变化或定性流畅度 | 实验环境、采样和结果来源 |
| 状态与架构 | 状态边界、组件/模块契约、微前端、数据流 | 降低耦合、支持独立演进、提升可维护性 | 不能仅凭用了状态库声称架构设计 |
| 设计系统 | token、组件 API、文档、可访问性、版本治理 | 提高一致性、减少重复实现 | 组件数量/复用率必须可核查 |
| 可访问性 | 语义化、键盘、焦点、对比度、读屏 | 改善可访问用户路径 | 不声称认证/合规，除非有依据 |
| 兼容与端适配 | 浏览器差异、设备尺寸、国际化 | 提升多环境可用性 | 明确实际支持范围 |
| 质量 | 单元/组件/E2E、类型、错误监控、回归策略 | 增强回归信心、缩短问题定位路径 | 覆盖率/缺陷率需可靠数据 |
| 工程化与交付 | 构建、依赖治理、CI、发布、监控 | 标准化交付、减少构建/发布摩擦 | 日常配配置不等于基础设施主导 |

## 3. 项目与成果表达

前端项目不写页面/功能菜单清单。优先选择能证明下列任一能力的公司核心项目：复杂交互、性能瓶颈、状态/架构演进、设计系统、质量与发布、跨端/可访问性。

虚构脱敏示例：

> 针对大规模树形数据展开时的卡顿，重构数据派生与分段渲染逻辑，减少无关节点重复计算，并补充交互回归用例，使复杂场景下的操作保持稳定。

没有可靠测量时不写“首屏提升 60%”；“保持稳定”也需要用户实际观察确认。

## 4. 前端禁忌

- “使用 Vue 完成用户、角色、菜单页面”等功能列表。
- 把页面数量、组件数量、代码行数当成业务价值。
- 只写“像素级还原”“配合后端联调”，看不出个人工程价值。
- 未实际测量就写 FCP/LCP、包体积、渲染帧率或转化率提升。
- 只安装构建插件就声称“主导前端工程化”。
- 把设计、产品或团队指标归为个人成果。
- 隐藏关键词、技能进度条，或罗列大量框架却没有项目支撑。

## 5. 高价值追问

1. 用户完成哪项任务最容易卡住，你亲自改变了哪个交互或技术路径？
2. 性能问题如何被发现和复现，用了哪些分析工具，结果如何验证？
3. 状态应该放在本地、全局、服务端还是 URL，你当时如何取舍？
4. 组件/设计系统由谁定义 API 和版本边界，你承担了哪部分？
5. 浏览器、设备、无障碍或国际化要求是什么，如何测试？
6. 一次线上前端错误如何定位，监控和 source map/日志发挥了什么作用？
7. 构建或发布改造的基线和实际效果是什么，数据能否披露？

## 6. 职业阶段差异

- **应届/实习**：突出语义化 HTML、JavaScript/TypeScript 基础、状态思考、调试、测试和真实用户路径；不要只展示截图或组件库套用。
- **有经验工程师**：公司核心项目优先，呈现体验、性能、质量、工程化与跨角色协作的真实结果。
- **转型者**：保留原领域可迁移证据；转型证明项目应有完整交互、错误处理、质量与部署，而非静态页面。
- **高级工程师**：突出跨页面/应用架构、性能治理、设计系统、可观察性和技术取舍。
- **技术负责人**：叠加负责人策略，确认设计/产品/后端协作影响及决策边界，不能把团队 UI 产出全部归为个人。

## 7. JD 定制提示

- “性能优化”：需要实际瓶颈、分析方法和验证；只用了懒加载是部分或未证实。
- “组件库/设计系统”：需要 API、规范、版本、推广或治理证据；写过业务组件不等价。
- “微前端”：需要拆分动机、隔离/通信/部署取舍和运行结果；使用框架名不足。
- “可访问性”：需要真实实践与测试；不要把语义标签扩写成全面 WCAG 合规。
- “前端工程化”：构建、质量门禁、依赖/发布/监控至少有具体行动。
- 框架术语可以对齐 JD，但熟练度由项目频率、独立能力和复杂问题支撑。

## 8. 可辩护性检查

核心成果应能解释用户路径、浏览器运行机制、性能/错误分析过程、架构边界、测试策略和结果依据。无法解释框架选择、渲染瓶颈或质量结果时降低陈述强度。
