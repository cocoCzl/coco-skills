# 客户端与移动端工程师岗位策略

适用于 Android、iOS、Flutter、React Native、HarmonyOS，以及以端侧工程为主的桌面客户端岗位。核心是端侧体验、生命周期、性能、稳定性、平台约束和发布质量。

## 1. 路由与主线

确认目标平台、原生/跨端、业务客户端/基础设施、在线/离线场景和目标职级。若是 Web 前端使用 `frontend.md`；若岗位强调跨端服务闭环，可按真实证据补读 `fullstack.md`，但不要把客户端 + 简单接口自动称全栈。

## 2. 优先寻找的证据

| 能力域 | 高价值事实 | 可用结果 | 关键边界 |
|---|---|---|---|
| 生命周期与架构 | 页面/组件生命周期、状态、导航、模块化、依赖管理 | 降低状态错乱、支持模块演进 | 使用某架构库不等于架构主导 |
| 性能与资源 | 启动、渲染、卡顿、内存、电量、网络、包体 | 有依据的启动/帧率/内存变化或定性稳定性 | 必须说明设备、版本、采样环境 |
| 稳定性 | 崩溃/ANR、错误捕获、恢复、灰度、回滚 | 提高故障发现与恢复能力 | crash-free 数字需平台数据确认 |
| 离线与同步 | 缓存、弱网、冲突、重试、数据一致性 | 弱网/离线流程更可靠 | 明确数据丢失与一致性边界 |
| 平台集成 | 权限、通知、后台任务、系统 API、设备能力 | 支持真实端侧场景 | 不披露安全绕过或内部证书 |
| 跨端 | 平台抽象、原生桥接、差异化体验、版本兼容 | 降低重复实现、统一交付 | 代码复用率需可靠计算 |
| 质量与发布 | 单元/UI 测试、设备矩阵、商店发布、灰度、监控 | 增强发布可控性、减少回归风险 | 下载量/评分不能自动归因个人 |
| 隐私与安全 | 权限最小化、敏感存储、传输、合规处理 | 降低隐私风险 | 不声称合规认证，除非有依据 |
| 可访问性/国际化 | 辅助功能、字号、语言、RTL、区域格式 | 改善覆盖和可用性 | 明确真实测试范围 |

## 3. 项目与成果表达

优先公司核心应用或端侧基础设施项目，围绕真实用户路径和平台约束，而不是列页面。

虚构脱敏示例：

> 针对弱网下表单重复提交与状态丢失，重构本地草稿、请求幂等与失败恢复流程，使用户在网络切换后可以继续完成提交，并增强异常状态的可追踪性。

如幂等在服务端由他人完成，应明确用户只负责端侧请求标识和状态恢复。

## 4. 客户端/移动端禁忌

- 罗列 Activity/ViewController/页面或 SDK 接入数量。
- 把团队下载量、商店评分、DAU 或收入直接写成个人结果。
- 未测量就写启动速度、帧率、崩溃率、包体或耗电改善。
- 仅使用 Flutter/React Native 就声称跨端架构设计。
- 把普通 API 调用包装成全栈或后端架构。
- 暴露签名、证书、bundle 标识、内部分发地址、设备标识或安全配置。
- 写“适配所有设备/系统版本”但没有实际测试范围。

## 5. 高价值追问

1. 目标平台和实际支持的系统/设备范围是什么？
2. 最棘手的生命周期、状态、弱网或资源问题如何复现和定位？
3. 你亲自负责原生、跨端共享层或桥接的哪一部分？
4. 性能结论在哪些设备、版本和工具下测得？
5. 崩溃/ANR 如何归因、修复、验证并灰度发布？
6. 离线同步如何处理重复、顺序、冲突和恢复？
7. 发布、权限、隐私或商店审核中你承担了什么具体工作？

## 6. 职业阶段差异

- **应届/实习**：突出语言/平台基础、生命周期、状态、网络、存储、测试和可运行作品；不把 demo 包装成大规模生产应用。
- **有经验工程师**：公司应用中的性能、稳定性、弱网、平台集成和发布证据优先，个人应用只作补充。
- **转型者**：明确原生/跨端或 Web 到端侧的迁移路径，用转型项目证明平台机制，不只证明 UI 开发。
- **高级工程师**：模块化、跨端取舍、性能/稳定性治理、发布机制和端云边界更重要。
- **技术负责人**：叠加负责人策略，确认端侧技术决策、平台团队影响和实际技术参与。

## 7. JD 定制提示

- “性能优化”需工具、设备/系统范围和验证；修过一次卡顿不等于全面性能治理。
- “跨端架构”需平台抽象、原生桥接、差异处理和演进证据。
- “稳定性治理”需监控、归因、修复/灰度机制；只处理普通 bug 是部分证实。
- “发布经验”区分打包接入、商店流程、灰度/回滚和发布体系主导。
- “安全/隐私”只写实际权限、存储或传输处理，不扩写为合规专家。
- 平台语言和框架必须与真实项目频率及复杂度匹配。

## 8. 可辩护性检查

核心成果应能解释生命周期/线程模型、设备与系统约束、复现与 profiling 方法、失败恢复、测试矩阵、发布路径和结果口径。不能解释的性能或稳定性数字必须删除或降级。
