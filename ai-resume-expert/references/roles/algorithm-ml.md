# 算法与机器学习工程师岗位策略

适用于推荐/搜索、NLP、CV、预测、传统机器学习、深度学习和偏模型研发的 ML 工程岗位。简历要建立“问题定义 → 数据 → 方法/实验 → 评估 → 生产约束”的证据链，而不是堆模型名称或只报一个指标。

## 1. 路由与主线

确认目标属于算法研究/应用算法、机器学习工程、推荐/搜索、NLP、CV 或模型生产化。仅做 RAG、Agent、模型 API 接入通常路由到 `ai-llm.md`；数据管道为主路由到 `data-engineering.md`。

进一步确认岗位更重模型质量、工程部署、在线系统还是研究产出。论文/竞赛只在与目标岗位相关且能说明个人贡献时出现。

## 2. 优先寻找的证据

| 能力域 | 高价值事实 | 可用结果 | 必须确认 |
|---|---|---|---|
| 问题定义 | 目标、标签、约束、成功指标、业务/用户成本 | 让模型目标与真实决策对齐 | 用户是否参与定义，而非接受任务 |
| 数据 | 采样、清洗、标注、特征、泄漏、偏差、版本 | 改善数据可靠性和实验可复现性 | 数据规模与质量数字需来源 |
| 基线与实验 | baseline、消融、超参、误差分析、复现 | 证明改进来自何处、识别失败模式 | 不能只列“用了某模型” |
| 评估 | 离线指标、阈值、分层评估、置信/显著性、人工评估 | 与实际目标一致的可解释比较 | 指标、测试集和统计口径 |
| 模型方法 | 架构、损失、特征、训练/调优、迁移学习 | 有依据的模型质量或鲁棒性变化 | 个人提出/实现的具体部分 |
| 在线验证 | A/B、影子、灰度、反馈、漂移 | 真实线上影响或风险验证 | 在线指标不能由离线结果推导 |
| 推理工程 | 服务化、批/实时、延迟、吞吐、资源、压缩 | 在质量与性能间取得可解释取舍 | 环境、硬件和测量口径 |
| MLOps | 数据/模型版本、训练流水线、注册、监控、回滚 | 提升可复现、可追踪和运维能力 | 使用平台不等于设计平台 |
| 责任与安全 | 公平、偏差、隐私、滥用、失败边界 | 降低特定风险、明确使用边界 | 不声称全面消除风险 |

## 3. 成果表达

算法成果应同时给出问题、个人方法和评估条件。数字只有在真实记录和用户确认后使用。

无数字的虚构脱敏示例：

> 针对少数类别在总体指标中被掩盖的问题，重构分层评估与误差分析流程，并据此调整采样和阈值策略，使模型评审能够明确识别不同类别的失败边界。

有数字时还需说明数据集版本、划分、指标方向和是否为线上结果；正文可压缩，证据表保留口径。

## 4. 算法/ML 禁忌

- 罗列 Transformer、XGBoost、CNN、PyTorch 等模型/框架，没有问题与实验。
- 只报准确率/召回率，不说明基线、数据划分、指标口径或个人贡献。
- 在测试集上反复调参后仍称无偏评估，或忽略数据泄漏。
- 将离线提升自动写成收入、留存或线上转化改善。
- 仅调用开源模型/API 就声称模型研发、训练或算法主导。
- 竞赛团队成绩全部归个人，或把公开数据实验包装成生产项目。
- 无依据写准确率、召回率、AUC、延迟、成本或“达到 SOTA”。
- 暴露训练数据、用户样本、客户和未公开模型细节。

## 5. 高价值追问

1. 模型实际优化的目标是什么，为什么选该指标？
2. 数据从哪里来，如何划分，怎样避免泄漏和偏差？
3. baseline 是什么，你亲自改变了模型/特征/损失的哪一部分？
4. 做过哪些消融和误差分析，哪些尝试失败了？
5. 指标结果在哪个数据版本和评估流程中获得，是否能复现？
6. 离线指标如何与线上/业务目标连接？若未上线，应明确停在离线验证。
7. 推理的延迟、吞吐、硬件、批大小和质量取舍是什么？
8. 你在团队中负责数据、算法、工程、评估或上线的具体边界？

## 6. 职业阶段差异

- **应届/实习**：教育、研究/实习、课程/竞赛/开源优先；重点是严谨实验、个人贡献和基础，不把 notebook 包装成生产系统。
- **有经验工程师**：公司算法问题、数据/评估、上线约束和实际运行结果为主体，论文/竞赛按岗位相关性补充。
- **转型者**：保留原工程或领域证据；转型项目必须展示数据、baseline、评估和失败分析，不只调用库训练一次。
- **高级工程师**：问题定义、评估体系、模型/系统取舍、线上实验、漂移和跨团队落地更重要。
- **技术负责人/架构师**：叠加负责人策略，验证模型路线/平台决策权、风险和团队影响；不能因职级高就冒领实验实现。

## 7. JD 定制提示

- “模型训练/调优”：需要数据、训练与评估证据；API 调用不覆盖。
- “推荐/搜索”：需要候选/排序、特征、反馈或在线约束等真实领域证据；通用分类模型不等价。
- “MLOps”：需要可复现流水线、版本、部署/监控；在云 Notebook 训练是部分证实。
- “大规模”：只有可核查数据/服务规模才覆盖，不用模型参数量代替业务规模。
- “论文/前沿”：只列用户真实贡献和可公开成果，不虚构作者顺序或复现深度。
- “线上效果”：离线实验不得改写成线上业务结果。

## 8. 可辩护性检查

用户应能解释目标函数、数据划分、baseline、实验控制、误差分析、统计/业务意义、生产约束和失败尝试。无法解释指标口径或个人方法时删除数字、降低“研发/主导”强度或改成真实工程动作。
