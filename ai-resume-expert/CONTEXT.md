# AI Resume Expert

本上下文统一程序员简历专家领域中的核心语言，避免把求职目标与使用者已有经历混为一谈。

## Language

**目标岗位**:
使用者希望申请的职位，是决定简历定位、内容取舍与表达重点的基准。
_Avoid_: 职业、当前职业、求职方向

**当前职业背景**:
使用者已经实际拥有的工作、项目、技能与教育经历，是简历事实与证据的来源。
_Avoid_: 目标岗位

**程序员简历专家**:
面向受支持技术岗位，帮助使用者审查、组织和表达真实职业证据的简历专业领域；这是 AI 简历专家首版的职业范围。
_Avoid_: 全职业简历专家

**受支持技术岗位**:
首版深度覆盖后端、前端、全栈、客户端与移动端、测试开发、DevOps/SRE、云与平台工程、数据工程、算法与机器学习、AI 与大模型应用，以及技术负责人和架构师岗位。不包含产品、项目管理、UI/UX、纯技术支持、硬件电子和纯管理岗位。
_Avoid_: 相关技术岗位、所有技术岗位

**项目事实**:
能够从代码库、项目文档或其他材料中观察到的系统能力、技术选型、结构与约束。项目事实本身不证明使用者参与或主导了相关工作。
_Avoid_: 个人成果、个人贡献

**个人贡献**:
使用者实际承担并确认的任务、决策、行动与结果。只有个人贡献才能在正式简历中归属于使用者。
_Avoid_: 项目功能、团队成果

**待确认素材**:
从项目事实、原简历、版本历史或使用者描述中发现，但尚未由使用者确认归属、准确性或边界的简历候选信息。
_Avoid_: 已确认经历、正式简历内容

**优秀程序员简历**:
一份以真实可证明为前提、针对目标岗位取舍内容，并清楚呈现个人贡献、技术复杂度与结果价值的简历。它应当经得起面试追问，同时便于招聘者快速阅读和招聘系统解析。
_Avoid_: 技术栈清单、项目说明书、视觉作品集

**目标求职市场**:
使用者计划投递简历的国家或地区及其招聘惯例。首版深度支持中国大陆招聘市场。
_Avoid_: 简历语言、所在地

**简历语言**:
简历最终内容所使用的语言；语言转换不等同于适配另一求职市场。首版深度支持中文简历。
_Avoid_: 目标求职市场、翻译质量

**STAR 证据单元**:
用于核实经历的结构化事实组合，包括场景、任务、行动与结果。它服务于访谈和成果整理，正式简历无需显示 S/T/A/R 标签，也不适用于个人信息、技能或教育等非经历内容。
_Avoid_: STAR 四段式简历、所有内容强制 STAR

**目标职级**:
使用者希望申请的岗位层级，例如初级、中级、高级、技术负责人或架构师；它与目标岗位共同决定简历应展示的能力深度。
_Avoid_: 工作年限、当前职级

**岗位基准版**:
未绑定具体招聘 JD，依据目标岗位、目标职级和已确认经历生成的简历版本。
_Avoid_: 通用简历、JD 定制版

**JD 定制版**:
针对一份具体招聘 JD 的职责、要求与关键词重新取舍和表达内容的简历版本。
_Avoid_: 岗位基准版、ATS 保过版

**用户确认事实**:
由使用者明确确认真实、准确且可归属于自己的经历信息；即使没有代码或文档佐证，也可以成为正式简历内容。
_Avoid_: 已独立验证事实、待确认素材

**证据冲突**:
使用者陈述、原简历、代码、项目文档或其他材料对同一事实给出无法同时成立的说法。冲突内容在澄清前不能作为正式简历事实。
_Avoid_: 信息缺失、措辞差异

**简历素材清单**:
按已确认、待确认和缺失状态整理的候选经历与事实集合，用于生成简历前的访谈和取舍。
_Avoid_: 简历初稿、项目功能清单

**信息缺口**:
生成目标岗位简历仍缺少的关键事实，例如个人角色、关键行动、技术方案或真实结果。
_Avoid_: 证据冲突、措辞待优化

**Markdown 初稿**:
达到最低证据门槛并完成事实、岗位适配、保密与可辩护性自审后，供使用者审阅确认的完整简历文本。仅有章节标题或大量占位符的内容属于简历骨架，不属于 Markdown 初稿。
_Avoid_: 简历骨架、正式 PDF

**最低证据门槛**:
生成 Markdown 初稿前必须具备目标岗位与职级、基本任职或教育时间线，以及每段入选经历中已确认的个人角色、关键行动或技术方案和真实结果；核心技能需有经历支撑，且不存在未解决的事实冲突或保密风险。联系方式可以在初稿阶段缺失，但最终 PDF 前必须补齐并确认。
_Avoid_: 章节齐全、信息数量、带占位符骨架

**致命问题**:
可能导致简历被直接淘汰、关键事实失真、目标严重错位或内容无法被可靠阅读的问题。单纯的措辞和美观偏好不属于致命问题。
_Avoid_: 所有缺点、一般改进项

**JD 要求覆盖**:
使用已证实、部分证实、未证实或不相关来表示简历证据与某项招聘要求的关系。
_Avoid_: ATS 匹配率、录用概率

**原简历**:
使用者提供用于诊断或优化的既有简历，是候选经历和既有表述的来源，而不是已经验证无误的事实集合。
_Avoid_: 已确认事实、正式简历

**ATS 友好 PDF**:
文字可选择、阅读顺序明确、信息层级稳定，便于招聘系统和招聘者读取的 PDF 简历。它不代表通过任何特定 ATS，也不代表获得面试。
_Avoid_: ATS 保过版、纯文本丑版

**现代技术型极简风**:
通过清晰字体层级、统一网格、留白、对齐、细分隔线和克制强调色呈现专业感的默认简历视觉风格。它保持单栏和黑白打印可读，不使用花哨背景、技能进度条或装饰性图表。
_Avoid_: 海报风、作品集风、纯文本无排版

**职业证据库**:
经使用者明确选择后在本地保存的可复用职业事实集合，包含已确认的任职、项目、技能和 STAR 证据。它不是源码归档，不包含密钥或无关公司资料，也不会自动写入开源 Skill 目录。
_Avoid_: 简历文件、用户画像、源码备份

**可核查量化结果**:
能够由可靠输入计算、追溯或合理解释，并由使用者确认的数字或范围型成果。
_Avoid_: 模型估算、无依据百分比、代码规模推导的业务成果

**真实定性结果**:
缺少可靠数字时，对实际效果进行不夸大的客观描述，例如降低操作复杂度、增强可追踪性或提高部署稳定性。
_Avoid_: 模糊赞美、伪量化结果

**可披露项目事实**:
已经公开或经使用者确认可以写入简历，且不会暴露公司、客户、系统或个人敏感信息的项目事实。
_Avoid_: 所有项目事实、内部细节、源码摘录

**保密脱敏**:
在保留经历价值的同时，将不可披露的内部名称、标识和实现细节替换为安全的业务类别或技术概括。
_Avoid_: 删除全部技术细节、仅替换项目名称

**岗位写作策略**:
针对一类受支持技术岗位，规定应优先寻找、验证和呈现哪些能力证据的专业规则。它叠加在通用简历规则之上，并可继续接受具体 JD 的定制。
_Avoid_: 通用程序员模板、JD 关键词复制

**投递就绪简历**:
事实已确认、目标已对齐、没有未解决的致命问题或保密风险，并由使用者确认定稿的 1～2 页简历。它应兼顾 ATS 可读性与专业排版，但不保证通过筛选、获得面试或被录用。
_Avoid_: 完美简历、ATS 保过简历、录用保证

**技能熟练度**:
由实际使用频率、独立完成能力、复杂问题处理和原理深度共同支撑的技能掌握程度。技能百分比、进度条和没有经历证据的“精通”不属于可信熟练度表达。
_Avoid_: 自评分数、技能进度条、无证据精通

**岗位定向版本**:
围绕一个明确目标岗位选择和组织证据的简历版本。不同目标岗位通常对应不同版本，只有岗位本身属于明确交叉方向时才合并定位。
_Avoid_: 一份通投简历、多岗位并列标题

**职业阶段**:
使用者当前经历所处的阶段，包括应届或实习、有经验工程师、技术方向转型，以及技术负责人或架构师阶段。职业阶段影响证据重点和简历结构，但不等同于目标职级或单纯工作年限。
_Avoid_: 目标职级、工作年限

**证据差距**:
使用者现有已确认经历尚不能支撑目标岗位某项要求的状态。证据差距只能通过真实经历建设来弥补，不能通过改写、关键词堆叠或虚构内容消除。
_Avoid_: 信息缺口、措辞问题、待确认素材

**PDF 验收**:
对最终 PDF 的中文字体、分页、截断、链接、页数和整体可读性进行检查的交付门槛。仅成功创建 PDF 文件不代表已经通过验收。
_Avoid_: PDF 转换成功、文件存在

**自适应访谈**:
根据目标岗位、现有材料和信息缺口，优先询问当前最影响简历质量的问题；已有答案不重复询问，证据充分时停止访谈。用户可以选择切换为批量结构化问卷。
_Avoid_: 固定问卷、无休止追问、重复提问

**证据追踪表**:
在正式简历之外，将关键经历陈述关联到用户确认、原简历、代码、文档或可核查计算，并记录确认与保密状态的审查材料。
_Avoid_: 简历脚注、公开引用、源码索引

**修改对照**:
在原简历之外展示关键内容的原文、优化后文本、修改原因和证据依据的审查材料。它允许使用者接受或否决修改，不替代原文件。
_Avoid_: 覆盖原稿、仅给最终版本、无理由改写

**最小必要个人信息**:
用于联系和识别候选人的姓名、手机号、邮箱、所在城市、专业主页链接及目标岗位。与岗位无关的敏感身份信息不属于默认简历内容。
_Avoid_: 完整个人档案、身份证信息、默认附照片

**证据化关键词**:
与 JD 用语一致且能够由已确认经历支撑的岗位关键词。没有事实证据的技能词、隐藏文字和机械重复不属于有效 ATS 优化。
_Avoid_: 关键词堆砌、隐藏白字、未掌握技能

**面试可辩护性**:
使用者能够说明简历核心陈述的背景、个人作用、方案取舍、问题处理和结果依据。无法合理解释的成果或高熟练度技能不能进入投递就绪简历。
_Avoid_: 背诵简历、包装话术、无法追问的技术点

**有限降级**:
目标岗位不在受支持范围时，仅提供通用事实整理和基础诊断，不声称具备该职业的专家策略，也不把结果标记为投递就绪。
_Avoid_: 全职业专家模式、静默套用程序员模板

**简历信息架构**:
根据目标岗位、职业阶段和证据价值选择、排序简历章节的结构。核心信息保持稳定，实习、项目、开源、论文、专利、竞赛、证书或奖项等章节仅在相关时出现。
_Avoid_: 固定 Java 模板、所有章节必填

**授权材料**:
使用者有权让当前 AI 环境处理，并已理解相应平台数据政策的简历、代码、文档或其他输入材料。拥有本地文件路径本身不等同于获得处理授权。
_Avoid_: 所有本地文件、未经确认的公司资料

**诊断模式**:
识别并解释原简历问题，但不自动改写整份简历的工作模式。
_Avoid_: 优化模式、静默重写

**优化模式**:
在诊断和证据确认基础上生成修改对照与新版 Markdown 初稿的工作模式。
_Avoid_: 诊断模式、直接覆盖原简历

**完整简历诊断**:
同时检查内容、证据、目标岗位适配和视觉排版的原简历审查。缺少渲染能力时只能称为文本诊断，并需明确未检查视觉排版。
_Avoid_: 仅文本提取、未渲染的版式判断

**职业事实真源**:
独立于任何目标岗位和简历措辞的已确认职业事实、STAR 证据、技能证据、来源与保密状态集合。
_Avoid_: JD 定制文案、未确认推断

**简历文案**:
从职业事实真源中选择事实，并针对某一目标岗位形成的表达。文案优化不会产生新的职业事实。
_Avoid_: 职业事实、证据来源

**项目入选建议**:
依据目标岗位相关性、个人贡献、技术复杂度、结果价值、时间新旧和面试可辩护性，对候选项目进行排序并解释取舍的建议。使用者保留最终选择权。
_Avoid_: 技术栈数量排序、项目规模排序、无理由筛选

**公司核心项目**:
有工作经验的使用者在任职期间参与、最能证明目标岗位能力的项目，作为对应公司经历的一部分呈现。
_Avoid_: 与工作经历割裂的重复项目、团队全部项目

**转型证明项目**:
当公司经历尚不能证明目标方向时，用于补充关键目标岗位证据的真实个人或开源项目。它必须明确标注来源，不能伪装成公司经历。
_Avoid_: 公司项目、练手功能清单、虚构商业项目

**扫描覆盖声明**:
说明代码库分析实际查看、跳过和无法读取范围的记录。定向分析或抽样分析不能被描述为完整全库分析。
_Avoid_: 已读完整代码库、未披露抽样

**对话式职业访谈**:
结合使用者已经提供的上下文，以自然、专业且具体的方式一次询问一个高价值问题，并在有帮助时给出回答方向。它不冒充真人，不使用机械问卷、空泛夸奖或诱导性包装。
_Avoid_: 审问式访谈、表单朗读、虚假共情、诱导夸大

**候选回答方向**:
AI 根据现有材料提出、用于帮助使用者回忆或澄清的可能答案。它不是事实，允许使用者全部否定，只有明确确认后才能成为职业证据。
_Avoid_: 预填事实、默认确认、诱导性答案
